# ERC-8380 minimum coherent repair options

This is a recommendation, not an external edit or authorization to implement one. Current pins and exact formulas are in the alignment audit.

| Option | Files/layers affected | Proof/vector compatibility | Domains and migration | Assessment |
|---|---|---|---|---|
| A: align to current ERC-8380 draft | Reference src/libraries/CapabilityCommitment.sol and SPEC.md tags; Noir hash.nr/main.nr with exact Keccak/packing constraints; explicit bytes32/Field representation; regenerated verifier/VK and adapter if encoding requires it; real parity tests and docs | Existing salt-passthrough proofs cannot be accepted as conformant. 1953 values differ; regenerate reference vectors. Preserve published 8380 Solidity vector as target. New circuit/VK needs new proof artifacts | Keep the current 8380/v1 draft relation. Any already-issued 1953 commitments require explicit separate legacy handling/reissuance; deployment usage is unknown, not presumed absent | Preferred intended semantic target; not merely renaming tags |
| B: align draft/Solidity to salt passthrough | Normative derivation, both Solidity libraries, circuit/interface documentation, verifier assumptions, tests and issuance security claims | Existing tagged Keccak commitments cease to match. Would require entirely new vectors and security analysis | Eliminates hash domain separation; publishes salt as public C/N and drops envelope dependence. Cannot be an equivalent migration | Reject as a repair of the intended security relation; easier parity would remove the required property |
| C: version and support multiple relations | Explicit version/domain dispatch in specification, issuance record, Guard/verifier selection, libraries/circuits/VKs/tests; unambiguous acceptance policy per version | Proofs and records bound to their own version/key; no implicit alias or fallback. Separate real 1953 and 8380 lanes would each need validation | Prevent cross-version substitution. Specify legacy retirement/reissuance and avoid accepting old incomplete circuit as secure | Appropriate only with actual compatibility requirements; larger surface than A |

**Recommended alignment target:** the current draft's C8380 and N8380 tagged Keccak formulas, exact 32-byte field order, target/calldata action hash, and nine public input semantics. This is recommended alignment, not current verified behavior. Do not invent Poseidon, truncate hashes, reduce bytes32 modulo a field, or change public input representation without a normative encoding decision. If preserving every 256-bit input requires limbs/bytes or another constraint representation, specify and test that mapping explicitly; a nine-scalar declaration alone is not sufficient.

Smallest coherent closure includes circuit source, reproducible compiler/prover/verifier-key provenance, known-valid proof, and the A-G negative tests. Aligning source text without regeneration leaves proof semantics unverified. Finality/off-chain wording is a separate draft update and does not repair commitments. Existing proof deployments and migration impact are not independently known.

RSI Phase 3D remains BLOCKED until these relations and transport are pinned and independently reproducible. No external changes, RSI implementation or commit/push are performed by this audit.
